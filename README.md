# ИИ-ассистент: анализ судебных документов (хакатон «ИИ-ассистенты для энергетики», трек №2)

Конвейер распознавания и извлечения данных из PDF-сканов судебных актов (арбитраж):
**PDF → OCR → структурированный JSON → Excel** — полностью локально, на open-source стеке.

## Возможности
- OCR сканов: **qwen3-vl:8b** (vision-модель Ollama) с автоматическим **fallback на PaddleOCR** при пустом/коротком результате;
- извлечение полей: суд, № дела, дата вынесения, судья, взыскатель, должник (ИНН, адрес), суммы (долг/неустойка/госпошлина/итого), реквизиты получателя — **qwen2.5:14b** → строгий JSON;
- составной ключ документа: **№ дела + суд + адрес должника** (№ дела сам по себе не уникален);
- **нормализация OCR-шума**: «1194З5» → «119435», «667ООО» → «667000», даты к дд.мм.гггг, суммы к float;
- **контроль качества**: контрольная сумма ИНН (как у ФНС), сомнительные поля помечаются ⚠️ в GUI/JSON;
- **мультиязычность**: латиница/иероглифы распознаются; иностранный текст переводится на русский (имена, названия и реквизиты не переводятся);
- экспорт сводки в Excel для юриста.

## Быстрый старт (5 шагов)

```bash
# 1. Python 3.13+ и виртуальное окружение
python -m venv .venv
.venv\Scripts\activate          # Windows
# source .venv/bin/activate     # Linux/macOS

# 2. Зависимости (внимание: paddlepaddle зафиксирован на 3.2.2 — 3.3.1 сломан на Windows)
pip install -r requirements.txt

# 3. Модели Ollama (скачаются один раз, ~15 ГБ суммарно)
ollama pull qwen3-vl:8b
ollama pull qwen2.5:14b

# 4. Обработка папки с PDF
python pipeline.py "C:\path\to\pdfs"

# 5. Excel-сводка
python excel_export.py --input СВОДКА_результатов.json --output документы_судов.xlsx
```

Результаты пишутся рядом с PDF: `*_text.txt` (распознанный текст), `*_result.json` (поля),
`СВОДКА_результатов.json` (все дела).

## Конфигурация (.env, опционально)

```env
OLLAMA_URL=http://127.0.0.1:11434
OCR_MODEL=qwen3-vl:8b
EXTRACT_MODEL=qwen2.5:14b
```

## Структура
| Файл | Назначение |
|------|------------|
| `pipeline.py` | PDF/сканы → OCR (гибрид) → нормализация → JSON → сводка |
| `normalize.py` | нормализация ИНН/дат/сумм + контрольная сумма ИНН |
| `extract_fields.py` | извлечение полей из текста (для экспериментов) |
| `excel_export.py` | сводка → Excel юристу |
| `sample/` | примеры текстов судебных приказов (тест извлечения) |

## Проверка на ловушке
Два разных должника с одинаковым № дела `2-456(86)/2020` различаются по адресу
(`sample/пример_приказ.txt` vs `sample/пример_приказ2.txt`) — адрес обязательное поле составного ключа.

## 🖥 GUI-приложение (v3)

`pythonw prikazy_gui.py` — окно для работы без консоли: выбор файла или папки,
живой лог процесса, таблица карточек дел. Возможности:
- **настраиваемая папка по умолчанию** — кнопка «📌 По умолчанию» запоминает целевую папку
  (путь сохраняется между запусками; при выборе файла предупреждает и предлагает сохранить папку файла);
- колонки настраиваются ПКМ по таблице (как в MetaTrader), выбор сохраняется;
- двойной клик по строке — полная карточка JSON; статус строк: ✅ / 🌐 (перевод) / ⚠️ (сомнительные поля);
- тёмная и светлая тема (кнопка в верхней панели), статус-бар с прогрессом и готовностью.

## 📎 Форматы входных файлов (v2)

- PDF-сканы (страницы-картинки);
- **цифровые PDF** (есть текстовый слой) — обрабатываются мгновенно, без OCR;
- **изображения JPG/PNG/TIFF/BMP/WEBP** — скан без PDF-обёртки;
- папка сканируется **рекурсивно** (подпапки тоже), остальные файлы пропускаются.

## 🌍 Мультиязычность и перевод

Реальное дело из выборки: **A40-258376** — ответчик финская компания
**Fingrid Oyj** (Läkisepäntie 21, 00620 Helsinki) — латиница и кириллица
в одном документе распознаются и извлекаются корректно. PaddleOCR поддерживает 100+ языков.

Если распознанный текст документа явно иностранный (например, китайский/английский/финский),
pipeline автоматически переводит его на русский локальной моделью **qwen2.5:14b**:
имена, названия компаний, адреса, номера дел, даты и суммы при переводе **не изменяются**.
Перевод сохраняется в JSON карточки (`translation`), в GUI строка помечается 🌐.

## 🔧 Нормализация и контроль качества

После извлечения все значения проходят постобработку (`normalize.py`):
- **ИНН**: буквы, похожие на цифры (О→0, З→3, В→8, I/l→1, S→5…), затем только цифры;
  проверка **контрольной суммы ИНН** (10/12 знаков, как у ФНС);
- **даты**: «15.03.2023», «2023-03-15», «05.02.23» → единый формат дд.мм.гггг;
- **суммы**: «1 371 600,4 ₽» → `1371600.4`.

Если поле вызывает сомнения (ИНН не сходится по контрольной сумме, суммы не извлечены) —
в JSON карточки попадает `warnings` + флаг `suspicious`, в GUI строка помечается ⚠️
и требует ручной сверки по скану.
